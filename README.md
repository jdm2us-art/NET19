Краткое описание используемых решений
1. Архитектура сети
Выбрана топология «звезда» (Hub-and-Spoke): центральный офис — ядро сети, три удалённых мини-офиса подключены к нему через последовательные каналы. Такая схема оптимальна для компании с одним головным офисом и несколькими филиалами: весь трафик между офисами проходит через центральный маршрутизатор, что упрощает управление, контроль безопасности и масштабирование (при добавлении нового офиса достаточно подключить его к свободному порту R0).

2. Коммутационная инфраструктура центрального офиса
Использована двухуровневая модель:

Уровень ядра — многоуровневый коммутатор Cisco 3560 (CORE-SW). На нём включена маршрутизация (ip routing), созданы SVI-интерфейсы для каждого отдела — они выполняют роль шлюзов по умолчанию. Это позволяет отказаться от отдельного маршрутизатора внутри ЦО и обеспечить быструю межвлановую маршрутизацию на аппаратном уровне.

Уровень доступа — три коммутатора Cisco 2960 (ACC-SW1/2/3), каждый обслуживает свою группу отделов. Соединение с ядром — транковые порты (802.1Q) с ограничением списка разрешённых VLAN.

Разделение на VLAN по отделам (VLAN 10–50) + отдельный VLAN 60 для Wi-Fi, принтеров и камер видеонаблюдения обеспечивает:

изоляцию широковещательных доменов;

логическую сегментацию по функциональному признаку;

возможность применения ACL между отделами (при необходимости).

3. Адресация
Использовано частное адресное пространство 192.168.0.0/16 для локальных сетей и 10.0.0.0/8 для транспортных сегментов. Каждому отделу выделена отдельная подсеть с маской /28 (14 хостов), что покрывает 7 сотрудников + периферию с запасом. Удалённым офисам выделены подсети /27, /28 и /28 (для офиса 3 маска увеличена с /29 до /28, так как 5 ПК + принтер + касса = 7 устройств не помещались в /29 с 6 хостами). Транспортные /30-сегменты экономят адресное пространство для point-to-point каналов.

4. Маршрутизация
Между всеми офисами настроен протокол динамической маршрутизации OSPF (Area 0). Выбор обоснован:

быстрая сходимость при изменении топологии;

отсутствие ограничения по количеству хопов (в отличие от RIP);

поддержка VLSM (что критично при использовании масок /30, /28, /27);

простота настройки и администрирования в масштабах небольшой корпоративной сети.

R0 выполняет роль граничного маршрутизатора (ABR/ASBR) — он связывает ядро ЦО с удалёнными офисами и анонсирует все сети в OSPF.

5. Удалённые офисы
Каждый мини-офис построен по схеме «маршрутизатор + коммутатор доступа»:

маршрутизатор Cisco 1941 — шлюз по умолчанию для локальной сети, WAN-интерфейс для связи с ЦО;

коммутатор Cisco 2960 — подключение рабочих станций, принтеров, камер.

В удалённых офисах VLAN не создавались (один отдел — одна подсеть), что упрощает конфигурацию и снижает нагрузку на оборудование.

6. Оконечные устройства
В соответствии с условием задания подключено по одному устройству каждого типа для проверки связности:

ПК — по одному на отдел (5 в ЦО, по 1 в каждом филиале);

принтеры — в ЦО, цехе и магазине;

камеры видеонаблюдения — в ЦО и на складе;

точка доступа Wi-Fi — в ЦО;

кассовое устройство — смоделировано ПК (Packet Tracer не поддерживает кассовые аппараты), IP-адрес зарезервирован в адресном плане.

7. Проверка работоспособности
Связность проверена:

внутри ЦО — ping между ПК разных VLAN (проверка SVI-маршрутизации);

между офисами — ping из каждого филиала в ЦО и между филиалами (проверка OSPF и транзитной маршрутизации через R0);

служебные команды — show ip ospf neighbor (3 соседа на R0), show ip route (наличие маршрутов с меткой O), show vlan brief, show interfaces trunk.

8. Итог
Спроектированная сеть удовлетворяет всем требованиям задания: 4 офиса объединены в единую корпоративную сеть, сотрудники всех филиалов имеют доступ к инфраструктуре центрального офиса, обеспечена логическая сегментация по отделам, адресный план оптимизирован, маршрутизация автоматизирована посредством OSPF. Схема легко масштабируется: для нового офиса достаточно выделить подсеть, добавить маршрутизатор и подключить его к свободному Serial-порту R0.
